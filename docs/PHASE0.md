# Phase 0：真机可行性验证指南

目标：拿到**至少一张 Uber Driver 真实订单弹窗**的结构化文字，确认报价、距离、时间能否从无障碍节点读到；读不到就确认必须走 OCR。

> 所有操作请在**停车状态**下进行。

## 方法 A：用 OfferPilot 自带的快照工具（推荐）

1. 安装 OfferPilot，开启无障碍服务（见 README）。
2. 「状态」页打开 **调试模式**。
3. 「调试」页：
   - 打开 **自动快照**：之后只要在 Uber Driver 里识别到疑似订单（有金额 / 距离 / 时间），就会自动保存一份；
   - 或点 **10 秒后抓取**，然后切回 Uber 等订单弹出；
   - 或在订单弹出时点系统的**无障碍按钮**（调试模式开启后出现在导航栏或无障碍快捷菜单）。
4. 回到「调试」页，点快照的 **查看文字**：能看到 `"$9.00"`、`"29.9 km"`、`"42 min"` 这类文字，说明节点可读；只看到空白、只有地图或按钮，说明需要 OCR。
5. 点 **分享** 把 JSON 发给开发者（或贴到项目里）。分享前可以检查一下，里面可能有商家名或地址。
6. 如果自动快照一份都没有，而你确实在 Uber 里看到了订单：说明文字不在节点里或格式与假设不同，请用「10 秒后抓取」或无障碍按钮手动抓一份。

快照包含：每个窗口的类型 / 包名 / 位置，以及目标应用窗口的完整控件树（class、id、text、contentDescription、bounds、clickable）。截图默认不保存，可在调试页开启「快照附带截图」。

## 方法 B：用 GKD 抓快照

1. 安装 GKD（https://gkd.li），按提示开启无障碍和悬浮窗权限。
2. GKD 设置 → 高级设置 → 开启**快照**相关选项（如“截屏快照”/“悬浮窗按钮”，以当前版本为准，说明见 https://gkd.li/guide/snapshot ）。
3. 在 Uber Driver 弹出订单时，点 GKD 悬浮按钮（或按其设置的截屏快照方式）保存快照。
4. GKD 里「快照记录」→ 选中 → 分享 / 导出 zip（包含截图和节点树 JSON）。
5. 把 zip 交给开发者。

注意：GKD 和 OfferPilot 同时开着无障碍服务没有问题，但验证完可以关掉 GKD。

## 需要从快照里确认的事项

| 项目 | 记录 |
|---|---|
| Uber Driver 包名（预期 `com.ubercab.driver`） | |
| 订单弹窗是独立窗口还是主窗口的一部分（windowType） | |
| 报价文字原样（如 `$9.00`、`CA$9.00`） | |
| 报价旁是否还有其他金额（加价、小费说明等） | |
| 距离是总距离，还是分段（取货 + 送达） | |
| 时间是总时长，还是分段 / 含“X min away” | |
| 接单按钮文字（如 `Accept` / `Match`） | |
| 是否有稳定的 view id（`viewIdResourceName`） | |
| 多点配送如何显示 | |
| 终点文字是否可读（Phase 2 城外判断用） | |
| 结论：节点可读 / 需要 OCR | |

## 拿到快照后怎么改

1. 把快照里的文字逐行粘到 OfferPilot「模拟」页的 *模拟屏幕文字*，看适配器输出是否正确。
2. 在 `core/src/main/kotlin/com/offerpilot/core/parser/UberDriverAdapter.kt` 的 `UberAdapterConfig` 中按真实文字调整关键字；如果距离是分段显示且确认应相加，打开 `sumLegsWhenNoTotal`。
3. 把真实快照的文字做成单元测试（去掉地址等隐私信息），放到 `core/src/test`。
4. 验证无误后把 `verifiedOnRealDevice` 设为 `true`。
5. 如果确认节点读不到 → 实现 `app/.../capture/OcrFallback.kt`（Phase 2）。

## 真机集成测试清单（PRD 10.2）

- [ ] 订单弹出后自动识别，1 秒内出结论
- [ ] 切到地图 / 其他应用后，悬浮提示立即消失，不读取其他应用文字
- [ ] 订单消失（接单 / 拒单 / 超时）后不再显示旧结论
- [ ] 同一订单不重复播报
- [ ] 识别不全时只说“订单信息不完整”，不给推荐
- [ ] 关闭无障碍权限后服务正常退出，悬浮提示消失
- [ ] 悬浮提示不遮挡接单按钮，不拦截触摸
- [ ] 运行一小时的耗电情况
